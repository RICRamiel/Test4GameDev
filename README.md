# Test4GameDev

Тестовое задание по игровой разработке на Unity.

## О проекте

Небольшая 2.5D игра, в которой игрок исследует этажи башни и постепенно продвигается вверх.

Основная задача проекта - реализовать игровую механику и интегрировать её в существующую архитектуру проекта с использованием:

- Zenject;
- ProjectContext / SceneContext;
- EventManager;
- существующего UI-слоя ScreenView / ScreenController;
- общего механизма перехода между сценами.

Визуальная часть сделана простой: для окружения используются Unity primitives и базовые UI-элементы. Основной акцент сделан на игровой логике, архитектуре и корректной работе переходов между сценами.

## Игровая механика

### Первый этаж

На первом этаже игроку необходимо собрать три предмета.

Управление:

- `WASD` / стрелки - перемещение персонажа;
- `Esc` - открыть меню паузы.

После подбора предмета он исчезает, а счётчик на экране обновляется:

```text
Предметы: 0 / 3
Предметы: 1 / 3
Предметы: 2 / 3
Предметы: 3 / 3
```

После сбора всех трёх предметов первый этаж считается завершённым.

### Второй этаж

На втором этаже реализована механика возврата на предыдущий этаж.

При первой попытке пройти через дверь игрок получает сообщение о том, что он что-то забыл, и должен вернуться на первый этаж.

После возврата на первый этаж появляется ключ.

После получения ключа игрок может снова подняться на второй этаж и открыть дверь.

Таким образом, прохождение зависит не только от перемещения игрока, но и от состояния предыдущего игрового этапа.

Состояние прохождения, необходимое для этой механики, сохраняется между сценами.

### Пауза

Во время игрового процесса по нажатию Esc открывается меню паузы.

Меню содержит следующие действия:

Continue - закрыть меню паузы и продолжить игру;
Main Menu - вернуться в главное меню;
Exit - завершить приложение.

При открытии паузы игровое время останавливается с помощью Time.timeScale = 0. При закрытии значение восстанавливается до 1.

Обработка паузы разделена на несколько компонентов:
```text
PauseInputHandler
        |
        | Pause action
        v
PauseController
        |
        +-- PauseView
        |
        +-- Continue
        |
        +-- Main Menu
        |
        +-- Exit
```
`PauseInputHandler` использует Unity Input System и отвечает только за получение действия паузы.
`PauseController` содержит основную логику открытия и закрытия паузы, управления Time.timeScale и обработки действий меню.
`PauseView` отвечает за отображение меню и предоставляет доступ к его кнопкам.
Переход в главное меню выполняется через существующий механизм событий:
```text
PauseController
        |
        | SceneTransitionEvent
        v
   EventManager
        |
        v
SceneTransitionService
        |
        v
 MainMenuScene
```
Завершение приложения выполняется через `Application.Quit()`.

`PauseInputHandler` создаётся через `CoreSceneInstaller` и используется только в игровых сценах. Главное меню не содержит игровой системы паузы.

## Переходы между сценами

Переходы между сценами выполняются через существующую событийную инфраструктуру проекта.

Игровые компоненты не вызывают `SceneManager.LoadScene` напрямую.

Схема перехода:

```text
Gameplay
    |
    | SceneTransitionEvent
    v
EventManager
    |
    v
SceneTransitionService
    |
    v
Unity SceneManager
```

Общий механизм перехода находится в `Core`.

Это позволяет игровым компонентам только сообщать о необходимости перехода, не занимаясь непосредственно загрузкой сцен.

Переходы между сценами можно выполнять многократно. Сценовые зависимости создаются и уничтожаются вместе с соответствующим `SceneContext`, а глобальные зависимости находятся в `ProjectContext`.

## Архитектура

Проект использует предоставленную архитектурную основу без создания параллельной системы.

### Core

В `Scripts/Core` находятся общие для проекта компоненты:

- `EventManager` - событийное взаимодействие;
- `EventsProvider` - типы событий;
- `SceneTransitionService` - общий механизм перехода между сценами;
- `UIController` - управление открытым UI-экраном;
- `ScreenView` / `ScreenController` - существующий UI-подход.

### ProjectContext

В `ProjectContext` находятся зависимости, жизненный цикл которых должен сохраняться между сценами:

- `EventManager`;
- `UIController`;
- `SceneTransitionService`;
- `GameState`.

`GameState` используется для хранения игрового состояния, необходимого при переходе между этажами.

### SceneContext

Сценовые компоненты регистрируются в соответствующем `SceneContext`.

Например, логика первого этажа регистрируется только в первой сцене:

```text
FirstScene
    |
    +-- SceneContext
    |
    +-- FirstFloorInstaller
            |
            +-- FirstFloorSetup
            +-- FirstFloorController
```

Это позволяет не создавать компоненты первого этажа в сценах, где они не используются.

### UI

UI построен на существующей схеме:

```text
UIController
    |
    +-- ScreenView
    |      |
    |      +-- ScreenController
    |
    +-- MainMenuView
    |      |
    |      +-- MainMenuController
    |
    +-- FirstFloorView
           |
           +-- FirstFloorControllerUI
```

Открытие экранов выполняется через `OpenScreenEvent`.

Например:

```text
FirstFloorController
        |
        | OpenScreenEvent("FirstFloor")
        v
   EventManager
        |
        v
    UIController
        |
        v
 FirstFloorView
```

## Запуск проекта

### Требования

Проект разработан для:

```text
Unity 6000.3.8f1
```

### Запуск

1. Открыть проект в Unity `6000.3.8f1`.
2. Открыть стартовую сцену - `Assets\Scenes\MainMenuScene`.
3. Запустить проект через `Play`.

### Основной сценарий проверки

1. Запустить игру.
2. Открыть игровой режим через главное меню.
3. Перемещать персонажа с помощью `WASD`.
4. Собрать три предмета на первом этаже.
5. Перейти на второй этаж.
6. Попробовать пройти через дверь.
7. Вернуться на первый этаж.
8. Найти появившийся ключ.
9. Снова перейти на второй этаж.
10. Использовать дверь для дальнейшего перехода.

Дополнительно проверить:

- повторные переходы между сценами;
- отсутствие дублирования глобальных объектов;
- корректное обновление счётчика предметов;
- сохранение состояния между сценами.

## Известные ограничения

Проект является небольшим тестовым заданием, поэтому некоторые элементы намеренно реализованы в упрощённом виде.

- Визуальная часть использует простые Unity primitives и базовые UI-компоненты.
- Количество игровых этажей ограничено необходимым для демонстрации механики.
- Игровой прогресс не сохраняется между запусками приложения.
- Часть игровых состояний предназначена только для текущего прохождения.
- Отдельные игровые механики, не требующиеся для демонстрации задания, не реализованы.
